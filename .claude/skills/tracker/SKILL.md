# tracker

Получает список URL страниц товаров, собирает цены через скилл `extract-price`, сравнивает их с предыдущим прогоном из репозитория `almaz-87/tracker-data` и выдаёт **только значимые изменения** — не сырые цены целиком. Каждый прогон сохраняется в `tracker-data`.

## Вход

Список URL — по одному на строку, через пробел или запятую. Например:

```
https://store.alnejoum.com.sa/en/almarai-barista-1-liter-almarai-barista-long-life-full-fat-milk-1l/p26347689
https://example-shop.ru/product/12345
```

- Убери пустые строки и лишние пробелы, оставь только строки, начинающиеся с `http://` или `https://`.
- Повторяющиеся URL обрабатывай один раз.
- Если ни одного URL нет — попроси пользователя прислать список ссылок.

## Алгоритм

Рабочие файлы (`prev.json`, `curr.json`, `diff.json`) держи в scratchpad-директории сессии.

1. **Собери текущий прогон.** Разбери вход в список уникальных URL (исходный порядок сохраняется). Для каждого URL по очереди вызови скилл `extract-price` (инструмент Skill, `skill: "extract-price"`, `args: <URL>`) и выполни его инструкции. Сбой на одном URL не останавливает обработку — у него все поля `null`. Собери JSON в формате из раздела «Формат файла прогона» и запиши в `curr.json`.
2. **Найди предыдущий прогон** — до сохранения нового:
   1. Если `tracker-data` не подключён к сессии — подключи его инструментом `add_repo` (`owner: almaz-87`, `repo: tracker-data`, `access: push`).
   2. Получи список файлов корня: `get_file_contents` (`owner: almaz-87`, `repo: tracker-data`, `path: /`, `ref: refs/heads/main`).
   3. Оставь только имена вида `YYYY-MM-DD.json` и возьми последнее по дате — это предыдущий прогон (может быть и сегодняшним, если сегодня уже был прогон).
   4. Прочитай его через `get_file_contents` и запиши содержимое в `prev.json`.
   5. Файлов прогонов нет — это **первый запуск**, сравнивать не с чем: переходи к шагу 5.
3. **Посчитай diff:** `python3 -I <каталог скилла>/diff.py prev.json curr.json > diff.json`. Скрипт сопоставляет товары по `url` и для каждого сравнивает `regular_price`, `sale_price`, `has_credit`; для цен считает изменение в процентах.
4. **Примени правила значимости.** Прочитай `KNOWLEDGE.md` в корне репозитория проекта и примени его правила к каждому товару из `diff.json`. Незначимые изменения (например, колебание цены на копейки) отбрасывай — в выход попадает только то, о чём стоит уведомлять.
5. **Сохрани прогон** в `tracker-data` — раздел «Сохранение прогона».
6. **Выведи результат** — раздел «Выход».

## Выход

Список **только значимых изменений**, сгруппированный по товарам, в исходном порядке URL. Сырые цены неизменившихся товаров не выводи.

```markdown
**Значимые изменения** (2026-11-02 vs 2026-11-01):

- https://store.alnejoum.com.sa/en/vimto-fruit-cordial-syrup-710-ml/p345193403
  - 📈 sale_price: 13.20 → 14.35 (+8.7%)
- https://store.alnejoum.com.sa/en/almarai-whipping-cream-1-liter/p312743505
  - ❌ товар пропал (страница недоступна или товар снят); последняя цена: 12.50
```

- `url` — полностью, без сокращений.
- Формулировки и значки событий — из таблицы правил в `KNOWLEDGE.md`.
- Значимых изменений нет — так и напиши: «Значимых изменений нет».
- Первый запуск — напиши: «Первый запуск — сравнивать не с чем. Прогон сохранён как базовый.» и выведи текущие цены таблицей `url | regular_price | sale_price | has_credit` (`null` → `—`).

В конце — одной строкой итог: сколько URL проверено, по скольким есть цены, сколько значимых изменений и сколько незначимых отброшено; затем ссылка на коммит в `tracker-data`.

Не выдумывай значения: в выход попадает только то, что вернул `extract-price` и что есть в предыдущем прогоне.

## Сохранение прогона

Каждый прогон — один файл `YYYY-MM-DD.json` в корне репозитория `almaz-87/tracker-data`, ветка `main`. История прогонов накапливается по датам прямо в этом репозитории.

Записывай файл только через GitHub MCP — каждая запись сразу становится отдельным коммитом. Не используй локальный `git clone`, `git commit` и `git push`.

1. Дата — текущая дата UTC: `date -u +%F` (например, `2026-11-02`). Время прогона — `date -u +%FT%TZ`.
2. Если файл за эту дату уже есть (найден в списке на шаге 2 алгоритма) — возьми его `sha` и перезапиши файл: один день — один файл, прошлая версия останется в истории коммитов. Нет — создай новый, без `sha`.
3. Запиши файл инструментом `create_or_update_file`:
   - `owner: almaz-87`, `repo: tracker-data`, `branch: main`, `path: YYYY-MM-DD.json`;
   - `sha` — только при перезаписи;
   - `message`: `Tracker run YYYY-MM-DD: N URL, M с ценами, K значимых изменений`;
   - `content` — содержимое `curr.json`, обычным текстом (не base64).
4. Если запись не удалась — покажи ошибку; список изменений при этом всё равно выведи.

Если инструмент GitHub MCP возвращает 404 на `tracker-data`, а репозиторий подключён, — попробуй другой подключённый GitHub-коннектор (встроенный «Интеграция с GitHub» — инструменты `mcp__github__*`).

### Формат файла прогона

```json
{
  "date": "2026-11-02",
  "run_at": "2026-11-02T08:07:11Z",
  "items": [
    {
      "url": "https://store.alnejoum.com.sa/en/…/p26347689",
      "regular_price": 6.39,
      "sale_price": 5.43,
      "has_credit": false
    },
    {
      "url": "https://store.alnejoum.com.sa/en/…/p312743505",
      "regular_price": null,
      "sale_price": null,
      "has_credit": null
    }
  ],
  "summary": { "total": 2, "ok": 1, "failed": 1 }
}
```

- В файл сохраняются все текущие цены (не только изменения) — это база для следующего сравнения.
- `items` — в исходном порядке URL; `url` — полностью.
- Отсутствующие значения — `null`. Других полей, кроме `url`, `regular_price`, `sale_price`, `has_credit`, у элемента нет.
- JSON с отступом в 2 пробела, UTF-8, без экранирования кириллицы.
