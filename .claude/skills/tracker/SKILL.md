# tracker

Получает список URL страниц товаров, для каждого вызывает скилл `extract-price` и собирает результаты в одну таблицу.

## Вход

Список URL — по одному на строку, через пробел или запятую. Например:

```
https://store.alnejoum.com.sa/en/almarai-barista-1-liter-almarai-barista-long-life-full-fat-milk-1l/p26347689
https://example-shop.ru/product/12345
```

- Убери пустые строки и лишние пробелы, оставь только строки, начинающиеся с `http://` или `https://`.
- Повторяющиеся URL обрабатывай один раз.
- Если ни одного URL нет — попроси пользователя прислать список ссылок.

## Алгоритм

1. Разбери вход в список уникальных URL, сохрани исходный порядок.
2. Для каждого URL по очереди вызови скилл `extract-price` (инструмент Skill, `skill: "extract-price"`, `args: <URL>`) и выполни его инструкции. Запомни полученный JSON `{ regular_price, sale_price, has_credit }` и поле `error`, если оно есть.
3. Ошибка на одном URL не останавливает обработку: запиши её и переходи к следующему.
4. Когда все URL обработаны — выведи таблицу из раздела «Выход».
5. Сохрани результат прогона в репозиторий `almaz-87/tracker-data` — см. раздел «Сохранение прогона».

## Выход

Markdown-таблица, одна строка на URL, в исходном порядке:

```markdown
| url | regular_price | sale_price | has_credit |
|---|---|---|---|
| https://store.alnejoum.com.sa/en/…/p26347689 | 6.39 | 5.43 | false |
| https://example-shop.ru/product/12345 | 12990 | — | true |
| https://www.amazon.sa/…/dp/B0CDBPTF4L | — | — | — |
```

- `url` — исходный URL полностью, без сокращений.
- `regular_price`, `sale_price` — числа как их вернул `extract-price`; `null` записывай как `—`.
- `has_credit` — `true` или `false`; для URL с ошибкой — `—`.

Если хотя бы по одному URL была ошибка, под таблицей добавь список:

```markdown
**Ошибки:**
- https://www.amazon.sa/…/dp/B0CDBPTF4L — страница недоступна: антибот-проверка
```

В конце одной строкой — итог: сколько URL обработано, по скольким получены цены, по скольким ошибки.

Не выдумывай значения: в таблицу попадает только то, что вернул `extract-price`.

## Сохранение прогона

Каждый прогон — один файл `YYYY-MM-DD.json` в корне репозитория `almaz-87/tracker-data`, ветка `main`. История прогонов накапливается по датам прямо в этом репозитории.

Записывай файл только через GitHub MCP — каждая запись сразу становится отдельным коммитом. Не используй локальный `git clone`, `git commit` и `git push`.

1. Дата — текущая дата UTC: `date -u +%F` (например, `2026-11-01`). Время прогона — `date -u +%FT%TZ`.
2. Если `tracker-data` не подключён к сессии — подключи его инструментом `add_repo` (`owner: almaz-87`, `repo: tracker-data`, `access: push`).
3. Проверь, есть ли уже файл за эту дату: `get_file_contents` (`owner: almaz-87`, `repo: tracker-data`, `path: YYYY-MM-DD.json`, `ref: refs/heads/main`).
   - Файла нет (404) — создаёшь новый, `sha` не нужен.
   - Файл есть (повторный прогон в тот же день) — возьми его `sha` и перезапиши файл: один день — один файл, а прошлая версия останется в истории коммитов.
4. Запиши файл инструментом `create_or_update_file`:
   - `owner: almaz-87`, `repo: tracker-data`, `branch: main`, `path: YYYY-MM-DD.json`;
   - `sha` — только при перезаписи;
   - `message`: `Tracker run YYYY-MM-DD: N URL, M с ценами, K ошибок`;
   - `content` — JSON из формата ниже, обычным текстом (не base64).
5. Сообщи пользователю ссылку на коммит или файл. Если запись не удалась — покажи ошибку; таблица из раздела «Выход» при этом остаётся результатом прогона.

Если инструмент GitHub MCP возвращает 404 на `tracker-data`, а репозиторий подключён, — попробуй другой подключённый GitHub-коннектор (встроенный «Интеграция с GitHub» — инструменты `mcp__github__*`).

### Формат файла

```json
{
  "date": "2026-11-01",
  "run_at": "2026-11-01T08:07:11Z",
  "items": [
    {
      "url": "https://store.alnejoum.com.sa/en/…/p26347689",
      "regular_price": 6.39,
      "sale_price": 5.43,
      "has_credit": false
    },
    {
      "url": "https://store.alnejoum.com.sa/en/…/p312743505",
      "regular_price": null,
      "sale_price": null,
      "has_credit": null,
      "error": "товар не найден: редирект на главную страницу"
    }
  ],
  "summary": { "total": 2, "ok": 1, "errors": 1 }
}
```

- `items` — в том же порядке, что строки таблицы; `url` — полностью.
- Отсутствующие значения — `null` (не `"—"`). Поле `error` — только у URL с ошибкой, у такого URL `has_credit` = `null`.
- JSON с отступом в 2 пробела, UTF-8, без экранирования кириллицы.
